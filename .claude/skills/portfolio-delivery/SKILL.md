# Portfolio delivery checklist

Every project should make it easy for a recruiter to understand what was built and verify that it works.

## Required artefacts

- Business problem, intended user and decisions supported.
- Architecture diagram and data flow.
- Data provenance, licence and synthetic-data statement.
- Data dictionary and database schema.
- Setup instructions and `.env.example`.
- Reproducible scripts and dependency declarations.
- Tests and instructions for running them.
- Dashboard screenshots or a short demo.
- Limitations, assumptions and future improvements.
- A short section explaining the developer's own technical decisions.

## Interview readiness

The developer should be able to explain:
- Why the project matters to the business.
- The grain and relationships of the data model.
- One key SQL query and one important KPI.
- How data quality is checked.
- Why a forecasting method was selected and how it was validated.
- How ERP and analytics responsibilities are separated.
- What failed during development and how it was debugged.
- What is simulated and what is genuinely implemented.

Do not claim experience with enterprise tools beyond what the project demonstrates.
